# 検索ページ空状態の改善 設計

日付: 2026-07-03
背景: UI/UX評価 (2026-07-03) の改善候補 #1。検索ページ未入力時に「曲が見つかりません」と表示され、「未検索」と「検索結果ゼロ」が区別できない。

## 原因

`SearchPage.tsx` が空クエリ時に `[]` を `SongList` に渡し、`SongList` は空配列を一律「曲が見つかりません」と表示するため。

## 決定

未入力時は SongList を描画せず、専用の空状態UIを表示する（ユーザー承認済み: 誘導文＋再生履歴）。

### 1. 新規フック `useRecentSongs(limit = 10)`

- 配置: `app/src/hooks/useRecentSongs.ts`
- `historyStore.history` を購読し、以下を返す:
  - `performanceId` を重複排除（最新の再生を優先、順序は新しい順）
  - `songPerformances` に存在しないID（データ更新で消えた演奏）は除外
  - 上限 `limit` 件（既定10）
- LibraryPage の履歴一覧は「重複を残す全履歴」なので共通化せず、検索用途専用とする

### 2. SearchPage の分岐

- 判定は `searchQuery.trim()` に統一（現状の truthy 判定では空白のみ入力で全曲表示になる不具合があり、これも解消）
- 空クエリ時:
  - 検索アイコン＋誘導文「曲名やアーティスト名で検索」
  - 履歴があれば見出し「最近再生した曲」＋ `SongList`（queue としてそのまま再生可能）
  - 履歴がなければ誘導文のみ
- クエリあり: 従来どおり件数＋結果。0件時の「曲が見つかりません」は本来の意味で機能する

### 3. テスト（TDDで先行）

- `useRecentSongs`: 重複排除 / 上限 / 存在しないIDの除外 / 履歴なしで空配列
- `SearchPage`: 未入力時に「曲が見つかりません」を出さない / 誘導文表示 / 履歴表示 / 空白のみ入力は未入力扱い / 入力時は結果表示

## 影響範囲

- 変更: `app/src/pages/SearchPage.tsx`
- 追加: `app/src/hooks/useRecentSongs.ts`, テスト2ファイル
- `SongList` の空配列メッセージは変更しない（検索0件・空プレイリスト等で引き続き使用）
