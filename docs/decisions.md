# Decision Records

## DR-001: end_time の自動補完方針

- **日付**: 2026-03-08
- **ステータス**: 保留
- **背景**: `song_performances.csv` の 2131 件中 1391 件 (65%) で `end_time` が未入力。現在 `build_app_data.py` では「次の曲の `start_time`」で代替している。
- **検討内容**: 弾き語り配信のため、曲の演奏終了タイミングが不定であり、楽曲の公式尺から正確な `end_time` を算出することが困難。MCやチューニングの時間も挟まるため、外部の音楽データベース（MusicBrainz 等）から取得した曲の長さをそのまま適用できない。
- **現行の対処**: 次の曲の `start_time` を前の曲の `end_time` として使用。最後の曲は `start + 300秒`（5分）で補完。
- **決定**: 現行方式を維持し、より正確な補完手法は今後の課題とする。音声解析や無音検出などのアプローチが考えられるが、費用対効果を見極めてから着手する。
