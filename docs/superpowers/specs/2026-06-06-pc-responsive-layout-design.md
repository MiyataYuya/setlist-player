# PC レスポンシブレイアウト 設計

- 日付: 2026-06-06
- 対象: `app/`（React 19 + Vite + MUI v7 + Zustand）
- ステータス: 設計合意済み（実装計画はこの後 writing-plans で作成）

## 背景・目的

セトリプレイヤーはモバイルファーストの単一カラム SPA。YouTube IFrame Player API の仕様上バックグラウンド再生ができず、ユーザーは PC で画面を見ながら使うことが多い。しかし現状は下部ナビ＋せり上がる全画面オーバーレイというモバイル前提のレイアウトで、PC の広い画面では一覧が横に間延びして使いにくい。

PC（広い画面）でも快適に使えるレスポンシブ対応を行う。**モバイルの挙動は一切変えない**。

## 採用する全体方針

PC 幅では **2 ペイン構成**を採る:

```
┌──────────┬─────────────────────┬──────────────────┐
│ 左サイド  │ メイン一覧            │ 右パネル           │
│ ナビ      │ (Home/Search/...)   │ (常設プレイヤー)    │
│ ホーム    │  曲・配信リスト       │  YouTube動画       │
│ 検索      │                     │  曲情報/♡/タグ      │
│ ライブラリ │                     │  シーク/コントロール  │
│          │                     │  キュー            │
└──────────┴─────────────────────┴──────────────────┘
```

- 一覧を見ながら、右ペインで再生・動画・キューが常に見える（PC の画面を最大活用）
- 検討した代替案: (A) 左ナビ＋下部プレイヤーバー（Spotify風）、(C) 上部ナビ＋中央寄せ（最小変更）。広い画面の活用度を重視し B（右常設パネル）を採用。

## しきい値（ブレークポイント）

- `useMediaQuery(theme.breakpoints.up('lg'))`（≈ 1200px 以上）で「PC（デスクトップ）」と判定
- それ未満（タブレット縦・スマホ）は**現状のモバイルレイアウトのまま**
- 中途半端なタブレット幅で崩すより、しきい値を高めに置いて安全側に倒す

## コンポーネント構成

DRY を重視し、再生画面の中身は共有コンポーネントに切り出してモバイル／PC 双方で使い回す。

| ファイル | 種別 | 役割 |
|---|---|---|
| `hooks/useIsDesktop.ts` | 新規 | `useMediaQuery(up('lg'))` をラップした PC 幅判定フック |
| `components/layout/navItems.ts` | 新規 | ナビ 3 項目（ホーム/検索/ライブラリ）の定義。`BottomNav` と `SideNav` で共有し重複を排除 |
| `components/layout/SideNav.tsx` | 新規 | 左サイドナビ（縦並び・ラベル付き）。現在ルートのハイライト、再生画面オープン状態の考慮はモバイルと同等 |
| `components/layout/DesktopShell.tsx` | 新規 | 左ナビ＋中央一覧（`Routes`）＋右パネルの 3 カラム枠 |
| `components/player/PlayerBody.tsx` | 新規 | 曲情報・お気に入り・タグ・シークバー・コントロール・キュー。現 `PlayerScreen` の中身（閉じるボタンを除く）を切り出し |
| `components/player/DesktopPlayerPanel.tsx` | 新規 | 右パネル本体＝動画プレースホルダ枠 + `PlayerBody`。曲未選択時は「曲を選択してください」 |
| `components/player/PlayerScreen.tsx` | 改修 | 閉じるボタン + `PlayerBody`。モバイルのオーバーレイ挙動は不変 |
| `components/layout/BottomNav.tsx` | 改修 | ナビ定義を `navItems.ts` から取得するよう変更（挙動不変） |
| `App.tsx` | 改修 | `useIsDesktop` でシェルを分岐。`YouTubeEmbed` を単一マウントで保持（下記） |

## 単一 iframe インスタンスの保持（重要制約）

`playerStore` はモジュールレベルの `_playerRef` で YouTube プレイヤーを単一インスタンスとして保持している。`YouTubeEmbed`（実 iframe）を React で別の親に移すと iframe が再生成され、再生が途切れる。

そのため:

- `YouTubeEmbed` は **`App.tsx` 直下に常に 1 個だけ**マウントする。モバイルシェル・PC シェルのどちらの DOM サブツリーにも内包させない（三項分岐で出し分けない）
- 配置は `position: fixed` のコンテナで行い、座標・サイズを `useIsDesktop` で切り替える:
  - モバイル: 現状どおり、せり上がる再生オーバーレイ上部の動画位置
  - PC: 右パネル上部の動画枠に重なる位置
- 各シェルには動画と同サイズの**プレースホルダ枠**を置き、レイアウトを崩さない
- リサイズでしきい値をまたいでも `YouTubeEmbed` はアンマウントされず、再生は継続する

座標合わせの具体手段（fixed 座標計算 / React Portal でプレースホルダへ投影 等）は実装計画フェーズで、単一マウント制約を壊さない範囲で最適なものを選ぶ。**「`YouTubeEmbed` を 1 回しかマウントしない」ことだけは設計として固定する。**

## 状態管理への影響

- `playerStore` は無変更
- `isPlayerOpen` はモバイル専用の概念として残す。PC では参照しない（右パネルは常設のため「開く/閉じる」がない）
- `MiniPlayer` / `BottomNav` は PC では `useIsDesktop` により非レンダリング（役割を左ナビ＋右パネルが引き継ぐ）

## データフロー

CSV → Vite プラグイン → 仮想モジュール → `src/data/songs.ts` のデータフローは無変更。ストアのセレクタ購読構造も無変更。レイアウト層のみの変更。

## テスト方針（TDD）

- **既存テストは全て不変で通ること**（モバイル挙動を変えないことの担保）
- 新規コンポーネント／フックにテストを先に書く:
  - `useIsDesktop`: `matchMedia` をモックし、幅に応じた真偽を検証
  - `SideNav`: ナビ項目の描画、クリックでのルート遷移、アクティブ表示
  - `PlayerBody`: 曲情報・コントロール・キューの描画（切り出し後も挙動同一）
  - `DesktopPlayerPanel`: 曲選択時／未選択時の表示分岐
- `matchMedia` は jsdom 環境でモックする。`renderWithProviders` を幅（デスクトップ/モバイル）指定できるよう必要に応じて拡張
- 単一 iframe マウントの検証: PC/モバイル両シェルで `YouTubeEmbed` が二重マウントされないことをテストで担保

## 非対象（YAGNI）

- 左ナビのアイコンのみ折りたたみ（細いレール）対応はしない（ラベル付き固定で十分）
- 動画の折りたたみ／別ウィンドウ化はしない
- 配信者の権利保護方針（DL・キャッシュ等の不実装、再生は必ず IFrame 経由）は本変更でも厳守
